# 复现与版本管理约定

## 基线、方法、适配分别记录

PyRUA-Lean 固定在 `e754cf43c822b91f4728777a78071fa4e012c371`。
作者代码、工具和提示不因整理仓库而修改。当前模块及附录的来源哈希见
[provenance.json](../provenance.json)。复现测试所用上游不提交到本仓库。

历史运行采用 Codex / GPT-6 Astra、high reasoning、RGB/no-VLA、on-demand images、
pure feedback，通常为 100 工具轮与 5400 秒。具体任务的原生动作预算必须看对应配置，
不能与工具轮数混用。模型标识和用量来自服务报告，未独立验证其内部实现。
历史服务地址、凭据和机器目录不构成方法贡献，也不写进源码。

历史 Lean 提示含来自公开任务代码的额外验收信息；与作者旧输入一致不代表符合
当前 RoboDojo 官方协议。旧简短任务句、Isaac Sim 6 兼容修改、插座刚体适配、
单次钥匙 1000 步特例均需保留标记，不能称作严格原版结果。
具体信息边界见原实现档案和 [RoboDojo 协议](https://robodojo-benchmark.com/leaderboard/protocol?lang=en)。

## 每轮实验

1. 先检查现有任务和资源，避免重复启动；服务器长任务用独立命名 tmux 并保存日志。
2. 固定代码提交、依赖、模型、提示词、工具、布局、seed、预算、资产与评测版本。
3. 先保留原版基线及问题证据，再开展明确标注的适配或改进。
4. 对照条件保持一致，不添加专属任务答案，不放宽评测，不事后挑成功布局。
5. 原生 verdict、Agent 自评、程序检查分别存储；基础设施失败、中止和未启动分别标记。
6. 保留全部预定尝试。未验证的失败原因只写为假设，单次成功不证明方法有效。
7. 记录配置、提示词和模块哈希，以及原始证据的稳定索引；完整日志留在仓库外。

禁止跨 episode 传递具体场景坐标、抓取偏移、布局答案与成功动作序列。
允许沿用作者规定的机器人运动学、相机标定及接口契约；不得引入未授权隐藏状态。

## Git 管理

- `main` 保存当前可测试的研究实现；修改前确认工作区和实验是否仍使用该版本。
- 一个提交对应一个明确变化；实验开始前固定完整提交和配置，不能只写“最新版”。
- 新问题先检查是否由已有规则、冗余记录或流程负担造成，优先删减和复用。
- 正常动作不额外增加逐动作验收，困难动作在失败后按需要拆分。
- 不覆盖冻结结果；历史方案用提交、标签或外部档案保留，不复制成多个活动源码目录。
- README 是使用入口，implementation 是当前实现，research_ideas 是想法；
  同主题优先原位维护，不为每次实验新增总结 MD。
- 实验资料只进入 `experiments/` 的配置、摘要与索引。运行日志、视频、资产、模型、
  虚拟环境及凭据排除出 Git；忽略规则不能替代提交前检查。

当前版本 `0.1.0.dev0` 表示研究起点，不宣称稳定接口或性能提升。
首次仓库整理没有运行新机器人实验，也没有调整历史实验配置。
