# 研究想法与状态

从原 `RESEARCH_IDEAS.md` 整理；保留研究目标与设计边界，历史实验过程见外部档案。
原文件哈希记录于 [provenance.json](../provenance.json)，不以本次整理改写历史结果。

## 核心目标

将反复出现、可计算和可验证的操作沉淀为程序，让 Agent 将推理用于规划、
信息获取、异常解释与纠错。在有限观察、推理和动作预算下，检验是否能提高成功概率。
减少上下文与幻觉是研究目标，当前没有足够对照证据证明这些收益。

## IDEA-001：按需要获取关键证据

失败后，先确定缺失的是当前静态状态，还是动作过程中发生了什么。
复用作者的初步定位、换视角、重新测量流程；必要时再观察重试过程。
关键帧应围绕有判别力的中间位姿或动作边界，并说明预期看什么、如何用于下一步。
全局与腕部图像可以互相佐证，不能只在最终结果时截图。

当前实现了静态 observe 和指定历史帧 review。自动发现关键帧、动作内条件捕捉、
安全侧方观察臂和多视角精度改进尚未作为完整机制接入当前恢复模块。
是否第一次失败就加入动态观察，需要比较额外时间与诊断收益，不能预设总是更好。

## IDEA-002：定位失败，并细化必要的执行片段

区分：当前步骤未做成；之前未做成却错误验收；已经做成但被后续动作破坏。
回到仍然成立的状态，找出首个未确认效果，针对它补信息、改变量、重新规划。
对于依赖新测量的困难动作，可拆成接近、重新定位、执行；简单动作仍允许一次完成。

当前 `localize`、`classify`、`conclude`、`outcome` 保存这个过程。
Agent 负责判断，程序维护结构。错误类型是可修正的假设，不要求因果证明后才能尝试。
不再增加一套与原检查重复的任务验收器，也不因“不确定”无条件增加检查轮数。

## IDEA-003：发现、验证并沉淀可复用程序

从真实执行中识别重复计算、几何测量、证据存取及流程维护，再验证是否值得固化。
复用的是算法、工具和获取信息的方法，不是历史布局、坐标或成功轨迹。
自动发现并积累新程序尚未实现；不能把上游已有三角测量等方法声称为新贡献。

## 从已有方法吸收的五个方向

1. 当前记录用于后续判断，完整历史留作回放；不把运行档案全塞回上下文。
2. 计划与执行分工：代码处理可计算反馈，Agent 解释视觉证据。
3. 在新信息成为后续动作前提的位置返回 Agent，更新依赖变量后再执行。
4. 通过更合适视角提供可见信息，减少单凭思考重复尝试。
5. 按当前困难选择执行片段长度；失败后细分，正常动作保持原有执行自由。

这些是设计借鉴与待检验方向，不作为“首次提出”的学术创新声明。
近期插入任务提示视觉与几何精度可能是瓶颈，但还需排除抓持、可达性、控制和物理适配因素。
