# 当前实现：失败后的证据与恢复记录

此文件描述当前 Git 中的实现。完整历史讨论与冻结实验保存在外部研究档案，
见 [实验索引](../experiments/README.md)。不把历史关键帧分支的能力算入当前模块。

## 职责与流程

正常动作仍使用作者原有 cell、反馈、异常和判断方式；不增加逐动作视觉验收。
主 Agent 识别失败后调用 `StaticRecovery`，模块不会自动检测物理失败或强制接管。

1. `begin` 固定这次需要恢复的目标、异常事实与证据引用。
2. `localize` 记录短动作链中已完成、失败、不确定、尚未尝试的部分。
3. `classify` 记录暂定原因与缺失信息；`unknown` 是有效选择。
4. 复用现有证据，或由 Agent 使用原观察、测量与 `move_to` 收集信息。
   `observe` 保存并显示当前视角、位姿和传入测量；`review` 回看指定历史边界。
5. `conclude` 记录要改变的变量、接下来执行的片段及验收条件；动作仍由原 API 执行。
6. `outcome` 记录主 Agent 对动作后当前证据的判断。

允许一次 cell 完成记录、规划、数字反馈处理与重试；需要解释新图像时才返回 Agent。
不要求先证明原因才允许探索。失败或不确定后需重新 classify；部分进展可继续规划。

## 接口边界

| 接口 | 程序负责 | Agent 负责 |
| --- | --- | --- |
| `begin` / `localize` | 结构校验、编号、记录 | 识别异常、拆分局部动作、提供事实 |
| `classify` | 保存暂定原因和问题 | 判断下一次需要什么信息 |
| `observe` | 当前帧、位姿、测量快照及图像交付 | 选择视角，必要时先用原 API 移动 |
| `review` | 按 step 读取、排序和交付历史图像与位姿 | 选择历史 step、解释过程；不是自动视频理解 |
| `conclude` | 保留补救计划与验收条件 | 将修正真正写入重试动作变量 |
| `outcome` | 检查证据索引、维护诊断状态 | 判断是否完成恢复目标 |

`review` 的 step 是 `robo.state().step`，不是 cell 编号或原生动作计数。
`observe` 传入的 measurements 是原对象快照，不会被重新测量或赋予新的有效时间。
`outcome` 能拒绝过时索引，但不能判断一张图片的解释是否正确。

记录按 episode 保存在原 workspace 内：`failure_*.md` 及相关 PNG。
只把后续决策需要的事实、尝试和引用送入记录，不重复打印完整历史。
不得将 episode 的具体坐标、布局答案或成功动作序列带入下一轮。

## 已验证与尚未验证

- 57 项原行为检查迁移到独立仓库；原 cell 集成测试直接使用固定作者源码。
- 新增 1 项接入检查：原提示与参数不变，只追加附录、复制模块并保存哈希。
- 当前模块与附录分别保持 `provenance.json` 中的实验哈希，未修改控制、验收或状态机。
- 可移植启动脚本尚未重新进行 GPU 闭环实验；旧实验仍对应原冻结启动脚本。
- 历史调用暴露过阶段顺序错误、误验收、很少使用 review，以及纠错后仍失败等情况。
  记录完整不代表原因诊断正确，更不保证任务成功。
- 自动中间帧选择、侧方观察臂及跨任务经验积累尚未实现。
